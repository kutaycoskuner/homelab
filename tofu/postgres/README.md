# tofu/postgres

PostgreSQL users as code: each user gets a strong password generated by OpenTofu, and optionally built-in roles such as read-only access to every database. Run with `tofu` on your PC ([Terraform and OpenTofu](../../docs/terraform.md)); it connects to the server over the home network or Tailscale.

## Files

| File | Holds | In git |
|---|---|---|
| `main.tf` | the provider (logs in as the admin), a generated password and a user per entry | yes |
| `variables.tf` | the inputs, with descriptions | yes |
| `outputs.tf` | the generated passwords (hidden unless asked for) | yes |
| `terraform.tfvars.example` | the inputs with placeholders | yes |
| `terraform.tfvars` | your values, including the admin password | no (gitignored) |
| `terraform.tfstate` | what tofu created, **including the generated passwords** | no (gitignored) |

## How it works

- **the admin** is the one login set by hand: PostgreSQL creates it on its very first start from `POSTGRES_USER` / `POSTGRES_PASSWORD` (later changes to those variables do nothing). tofu logs in with it to manage every other user
- **each entry in `users`** becomes a user that can log in, with a 40-character password of letters and digits (`random_password`), and the built-in roles listed for it
    - `pg_read_all_data`: read every table in every database, change nothing; e.g. for backups
- **app users** (`database = "<db>"`): full use of that one database, in the schemas listed (`schemas`, default `public`)
    - connect; use the schema and create new tables in it; read, write and delete in every table; use its sequences and functions
    - also on objects the admin creates later (default privileges)
    - the objects keep their owner: the app user can't `ALTER` or `DROP` tables it didn't create; schema changes on those are done as the admin
- **passwords** are generated once and stay the same on every `apply`; they're in the state and shown with `tofu output -json passwords`
- **removing an entry** deletes that user and its grants on the next `apply`

## Moving an app off the admin login

An app that connects as the admin can do anything to every database. To give it its own user:

1. add it: `<app> = { database = "<its database>" }`, then `plan` / `apply`; this only adds, the app keeps working with the admin login
2. switch the app's connection setting (e.g. `DATABASE_URL`) to the new user and its password from `tofu output -json passwords`, redeploy, check it works
3. once no app uses the admin any more, give the admin a strong password: `ALTER USER <admin> WITH PASSWORD '...'` on the server (e.g. `docker exec -it <postgres-container> psql -U <admin> -d postgres`), then the same password in `terraform.tfvars`; from then on only tofu logs in as the admin

## First run

From the repo root, in PowerShell (`'-chdir=...'` in quotes when the path contains a dot):

```powershell
Copy-Item tofu/postgres/terraform.tfvars.example tofu/postgres/terraform.tfvars   # then fill it in
tofu -chdir=tofu/postgres init
tofu -chdir=tofu/postgres plan    # 2 to add per user: its password and the user
tofu -chdir=tofu/postgres apply
```

## State

The state holds the generated passwords: keep it local and private, like the other tofu folders.
